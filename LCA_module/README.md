# LCA Module — Offshore Wind Farm Life Cycle Assessment

This module performs a cradle-to-grave Life Cycle Assessment (LCA) of an offshore wind farm.
It is built on top of the WINPACT sizing tool: component masses and O&M data are exported
automatically from WINPACT and consumed here. All results are expressed in three scopes:
**per turbine**, **full farm**, and **per functional unit** (1 kWh of net electricity generated).

---

## Prerequisites

### 1. Install Python dependencies

```
pip install pandas openpyxl pyyaml jupyter matplotlib
```

### 2. Add the ecoinvent database (REQUIRED — not included in this repository)

The ecoinvent database is **proprietary** and cannot be distributed publicly or committed to
GitHub. It must be added manually every time you clone or work on a fresh copy of the repo,
and must be removed (or left excluded by `.gitignore`) before pushing.

**Steps:**

1. Obtain the file `Cut-off Cumulative LCIA v3.12.xlsx` from the ecoinvent licence holder.
2. Place it directly inside the `LCA_module/` folder:

```
LCA_module/
└── Cut-off Cumulative LCIA v3.12.xlsx   ← place here
```

3. The `.gitignore` in this folder already excludes it, so it will not accidentally be pushed.

**Never commit this file.** Before running `git push`, confirm with `git status` that the
file does not appear as a staged or tracked change.

If you need to use a different version of the database, update `ECOINVENT_FILE` and `ECOINVENT_SHEET`
in `inputs/config.yaml` to match.

### 3. (Optional) Refresh WINPACT outputs

`inputs/technical_output.py` is auto-generated by `export_for_lca.py` (located one level up,
in the WINPACT root). If you have changed wind farm parameters in WINPACT, re-run that script
before running the LCA:

```
python export_for_lca.py
```

This overwrites `inputs/technical_output.py` with updated turbine counts, masses, energy output,
and O&M intervention rates.

---

## Running the Analysis

Open and run the Jupyter notebook:

```
jupyter notebook lca_analysis.ipynb
```

The notebook is the single entry point. It calls `lca_engine.py` to load the database, build
the inventory, compute impacts, and display results. No other script needs to be run directly.

## File Structure and Purpose

```
LCA_module/
├── lca_analysis.ipynb          ← Entry point: run this notebook to perform the LCA
├── lca_engine.py               ← All calculation logic (load DB, merge inventories, compute impacts)
├── inventory_masses.py         ← Component masses and quantities for every life stage
├── inputs/
│   ├── config.yaml             ← Project parameters, cable data, EOL factors, installation activities
│   ├── inventory_codes.yaml    ← Mapping of every component to an ecoinvent Activity UID
│   └── technical_output.py     ← Auto-generated from WINPACT (turbine masses, counts, energy, O&M)
└── .gitignore                  ← Excludes the ecoinvent database Excel file from git
```

### `lca_analysis.ipynb`

The user-facing entry point. Orchestrates the full analysis: loads the ecoinvent database,
selects life stages and scope, runs the engine, and presents results. Edit this notebook to
change which stages are included, which scope to report, or how outputs are displayed.

### `lca_engine.py`

Contains all calculation logic. The main functions are:

| Function | What it does |
|---|---|
| `load_ecoinvent_database()` | Reads the ecoinvent Excel file and builds a UID → impact factor lookup |
| `merge_inventories()` | Joins `inventory_codes.yaml` with `inventory_masses.py` by component name |
| `resolve_emission_factors()` | Looks up each UID in the database; warns on missing entries |
| `calculate_impacts()` | Multiplies quantity × emission factor for each component |
| `aggregate_by_stage()` | Sums component impacts up to life stage totals and a grand total |
| `validate_inventory_coverage()` | Checks all UIDs exist in the loaded database |

Do not edit this file unless you are extending the calculation methodology.

### `inventory_masses.py`

Defines the mass/quantity for every component across all life stages. Values come from two sources:

- **Turbine and substructure masses** — imported directly from `inputs/technical_output.py`
- **Electrical infrastructure and substations** — computed from parameters in `inputs/config.yaml`

Each leaf entry has three scopes:
```python
"Component Name": {
    "per_turbine": (quantity, "unit"),
    "full_farm":   (quantity, "unit"),
    "per_FU":      (quantity, "unit"),   # per kWh of net energy
}
```

Transport quantities are in `metric ton*km`. Installation and operation quantities are in `MJ`
(fuel energy). All other quantities are in `kg`.

If a component has no per-turbine breakdown (e.g. cables, substations), `per_turbine` is `None`
and that scope is skipped automatically during calculation.

### `inputs/config.yaml`

The main project configuration file. Contains:

- **Ecoinvent database settings** — file name, sheet name, header row, UID column
- **Impact categories** — which LCIA method and indicator column to extract from the database
- **Wind farm parameters** — distance to shore, cable lengths and cross-sections
- **Cable material fractions** — fraction of copper, polyethylene, lead, steel, glass per kg of cable
- **Offshore and onshore substation material masses** — total tonnes per material category
- **Installation activities** — fuel consumption rate (t/day) and duration (days) per activity type
- **Export cable material densities** — tonnes per km per material
- **EOL factors** — per material type: fraction recovered, recycled, incinerated, landfilled

Edit this file to adapt the module to a new project without touching Python code.

### `inputs/inventory_codes.yaml`

Maps every wind farm component to an ecoinvent Activity UID (a `UUID_UUID` string).
The structure mirrors the life stages used in `inventory_masses.py`:

```
Life Stage:
  Component Group:
    Component Name: "ActivityUUID_ProductUUID"
```

Life stages covered:

| Stage | Description |
|---|---|
| `Materials` | Raw material extraction (steel, copper, composites, etc.) |
| `Manufacturing` | Component fabrication and processing |
| `Transport` | Sea transport of components to site (metric ton*km) |
| `Installation` | Vessel fuel consumption during installation |
| `Operation` | Maintenance vessels + material replacements over lifetime |
| `Decommissioning` | Vessel fuel consumption during decommissioning |
| `End of life` | Recycling, incineration, and landfill of all materials |

To change which ecoinvent process is used for a component, replace its UID string with the
new one from the ecoinvent database.

### `inputs/technical_output.py`

Auto-generated by `export_for_lca.py` (WINPACT root). Contains:

- Number of turbines, turbine rating, capacity factor, lifetime, net energy output
- All per-turbine component masses (in tonnes)
- O&M intervention rates per component type (average replacements per year)
- Vessel hours by vessel type (CTV, LCN) over the project lifetime

**Do not edit this file manually.** Re-run `export_for_lca.py` from WINPACT to update it.

## Functional Unit

The functional unit is **1 kWh of net electricity generated** over the farm lifetime.
Net energy is taken from `ENERGY_NET_KWH` in `technical_output.py`, which is computed as:

```
ENERGY_NET_KWH = N_TURBINES × MW_PER_TURBINE × CAPACITY_FACTOR × LIFETIME_YEARS × 8760 h/yr × 1000
```

All `per_FU` quantities in `inventory_masses.py` are already pre-divided by this value.

## Impact Method

Currently configured for a single impact category:

| Label | Method | Category | Indicator | Unit |
|---|---|---|---|---|
| `GWP100 (kg CO2-Eq)` | IMPACT World+ v2.1, footprint | climate change | carbon footprint | kg CO2-Eq |

To add another impact category, add a new entry under `IMPACT_COLUMNS` in `inputs/config.yaml`
matching the exact method / category / indicator / unit strings in the ecoinvent sheet headers.

## Adapting to a New Project

1. **Update WINPACT** with the new turbine/farm parameters, then run `export_for_lca.py`.
2. **Update `inputs/config.yaml`** — change distance to shore, cable lengths, substation masses,
   installation activities, and any other farm-specific parameters.
3. **Update `inputs/inventory_codes.yaml`** if components change or new ecoinvent processes are needed.
4. Place the ecoinvent database Excel file in `LCA_module/` (if not already present).
5. Open and run `lca_analysis.ipynb`.

## Adding a New Life Stage

**In `inputs/inventory_codes.yaml`**, add a new top-level key:

```yaml
New Stage:
  Component Group:
    Component A: "activityUUID_productUUID"
    Component B: "activityUUID_productUUID"
```

**In `inventory_masses.py`**, add the same stage to `INVENTORY_MASSES`:

```python
"New Stage": {
    "Component Group": {
        "Component A": {
            "per_turbine": (mass_kg, "kg"),
            "full_farm":   (mass_kg * N_TURBINES, "kg"),
            "per_FU":      (mass_kg * N_TURBINES * FU_FACTOR, "kg"),
        },
    },
}
```

The key names must match exactly between the two files — `lca_engine.py` joins them by
`(life_stage, component_name)`.
